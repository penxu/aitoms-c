# Proposal

## Why

用户希望保留现有页面框架，通过一句自然语言完成应用开发，并能预览、发布、打包交付。现有项目已经实现分阶段生成、开发预览和源码导出，但缺少独立生产发布、版本管理以及完整的交付体验。

## What Changes

- 保留 `/` 首页、`/dashboard` 项目中心、`/app/{id}` 工作台以及现有导航和主要区块，升级视觉、响应式与交互状态。
- 把需求、设计、代码、验证、预览和交付连接为可恢复的任务，持续展示真实执行进度。
- 增加独立生产发布：冻结源码版本、构建、启动候选版本、健康检查、切换地址、回滚。
- 增加部署包：源码、锁文件、启动说明、环境变量示例、Dockerfile 和 Compose 配置；导出时排除秘密及运行数据。
- 所有成功状态必须来自真实结果；模型未配置、构建失败、网络失败和端口耗尽都有明确反馈。
- 不设置产品级 token 配额；保留取消、超时及有限自动修复，避免失控任务。

## Capabilities

### New Capabilities

- `app-generation`: 一句话生成、设计约束、进度恢复及真实验收。
- `production-release`: 独立发布、固定线上版本、失败保留旧版与回滚。
- `deployment-package`: 可复现部署包、秘密排除和可运行交付说明。
- `builder-experience`: 保留既有页面结构的精致视觉及完整操作反馈。

### Modified Capabilities

无直接修改。现有规格位于 `openspec/specs/*.md`，属于旧式扁平格式，当前 CLI 的规格清单无法识别；本次已直接读取相关原文。新增规格补充交付行为，不重命名或迁移旧文档。旧 marketing-site 中“唯一视觉基准”的约束，在本次 UI 升级范围内由用户最新的“框架按照原来的、提升质感”要求覆盖。

## Impact

- 复用 `app/src/lib/generation/`、`workspace/`、数据库与 runner；增加 release、package 模块及 API。
- 修改 marketing、dashboard、workspace 组件、样式、导出接口及部署配置。
- 新增发布记录与生产进程注册，保持原有项目数据和预览 URL 可用。
- 首版发布到运行平台的服务器，通过其公网域名访问；公网服务器、DNS、TLS 是实际部署环境的前提，不假定已有云账户。第三方云托管及自定义域名绑定另行扩展。
- 此变更仍为待审阅方案，未实施产品代码。
