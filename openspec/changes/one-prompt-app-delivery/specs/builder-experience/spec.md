# Builder Experience

## Purpose

在保留原有首页、项目中心和工作台结构的基础上，提供一致、精致、清晰的应用构建体验，让用户始终知道当前进度、真实结果和下一步操作，并能在桌面和移动设备上完成核心流程。

## ADDED Requirements

### Requirement: 保留现有页面结构
系统 SHALL 保留首页主要区块与顺序、项目中心侧边栏和工作台的对话及文件预览区域，在原结构内提升视觉层级及完成交付操作。

#### Scenario: 老用户导航
- **WHEN** 用户访问原有首页、项目中心和项目工作台路径
- **THEN** 原入口和主要区域仍可找到，项目数据保持可访问

### Requirement: 高品质一致视觉
系统 SHALL 使用统一的字体层级、色彩、间距、圆角、边框和阴影；生成、预览和发布状态必须有文字说明。

#### Scenario: 工作台状态可辨识
- **WHEN** 用户同时查看开发任务和线上版本
- **THEN** 界面清晰标注二者名称及状态，不仅依赖颜色区分

### Requirement: 所有核心操作有反馈
系统 MUST 为创建、生成、预览、发布、回滚及下载展示加载、成功和失败反馈，并在运行期间避免重复提交。

#### Scenario: 创建失败
- **WHEN** 项目创建 API 返回错误或网络不可达
- **THEN** 用户输入保留，界面显示错误并允许重试

### Requirement: 响应式与无障碍操作
系统 SHALL 在 375、768 和 1440 像素视口正常使用，允许键盘完成核心操作，提供焦点状态及输入和图标按钮的可访问名称，并尊重减少动态效果设置。

#### Scenario: 移动端工作台
- **WHEN** 用户在 375 像素宽度打开工作台
- **THEN** 侧边栏可收起，对话、代码和预览可以切换，页面没有横向溢出，主要操作可触达

### Requirement: 营销内容对应真实能力
系统 MUST 只将实际可执行的能力呈现为已支持；尚未接入的计费、第三方托管或集成不得显示伪造成功。

#### Scenario: 尚未接入第三方托管
- **WHEN** 用户打开发布面板
- **THEN** 面板展示实际可用的服务器发布及部署包选项，未实现的云服务不显示为可发布
