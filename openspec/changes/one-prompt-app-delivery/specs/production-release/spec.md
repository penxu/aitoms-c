# Production Release

## Purpose

让用户将已验证的应用发布为独立于开发预览的稳定版本，通过持久化的发布记录、候选版本健康检查、可靠的地址切换及回滚，保证后续修改或发布失败不会破坏已上线应用。

## ADDED Requirements

### Requirement: 独立生产版本
系统 SHALL 基于固定源码快照发布生产版本，提供与开发预览分开的稳定访问地址，并展示版本、时间和状态。

#### Scenario: 开发修改不影响线上
- **WHEN** 用户修改已经发布的项目源码或停止开发预览
- **THEN** 已发布版本继续提供原版本的服务，直到新发布成功切换

### Requirement: 发布前验收及原子切换
系统 MUST 在候选版本生产构建、进程启动和健康检查成功后才切换线上地址；失败时保留之前的可用版本。

#### Scenario: 第二次发布失败
- **WHEN** 新版本构建失败或健康检查失败
- **THEN** 发布记录显示失败日志，线上地址仍指向原版本

#### Scenario: 重复点击发布
- **WHEN** 同一项目正在发布时用户再次点击发布
- **THEN** 系统返回当前任务，不启动第二个冲突的发布任务

### Requirement: 版本回滚
系统 SHALL 允许将线上地址切换到历史成功版本，回滚前重新确认目标可启动且健康。

#### Scenario: 回滚旧版本
- **WHEN** 用户选择一个历史成功版本并回滚
- **THEN** 目标健康检查成功后线上地址切换，发布历史保留此次操作

### Requirement: 公网状态准确
系统 MUST 区分本地可访问和已配置公网访问，只有实际可达的公网地址才标记为线上地址。

#### Scenario: 仅本地运行
- **WHEN** 平台尚未部署到公网服务器或尚未配置公开访问源
- **THEN** 系统展示本地发布地址和部署说明，不将 localhost 标记为已上线公网

### Requirement: 发布中断恢复
系统 SHALL 在平台重启后将未完成发布标记为中断，重新核对活动版本可用性，且不错误切换到未验证候选版本。

#### Scenario: 构建中重启
- **WHEN** 平台在发布构建过程中重启
- **THEN** 该发布显示中断，原活动版本记录保留并在恢复后接受健康检查

### Requirement: 开发与生产业务数据隔离
系统 MUST 隔离开发预览、验证测试和生产业务数据，生产版本之间保持数据连续；首次发布不自动复制开发数据，并明确提示该行为。

#### Scenario: 开发测试不污染线上
- **WHEN** 已上线项目执行开发预览或自动表单测试
- **THEN** 测试数据不写入生产数据库，生产版本更新和回滚保留原有业务数据

#### Scenario: 首次发布数据提示
- **WHEN** 用户首次发布已有开发数据的项目
- **THEN** 发布面板提示生产数据库初始为空，开发数据保留且不被自动复制或删除
