# Deployment Package

## Purpose

让用户将生成应用作为独立、可复现的工程交付到其他服务器，提供完整源码、依赖锁定及明确部署步骤，同时避免将平台秘密、应用真实数据和机器专属内容泄漏到下载产物。

## ADDED Requirements

### Requirement: 可复现源码部署包
系统 SHALL 提供包含源码、依赖锁文件、环境变量示例、部署说明及容器启动配置的 ZIP，并包含源版本及验证状态清单。

#### Scenario: 新机器启动
- **WHEN** 用户在满足文档运行时条件的新环境解压部署包并执行文档中的安装和启动步骤
- **THEN** 应用能够构建、运行，并通过健康检查，无需依赖平台目录

### Requirement: 导出排除秘密与运行数据
系统 MUST 排除真实环境变量文件、密钥、数据库及旁路文件、日志、依赖、构建缓存、版本库内部数据及指向项目外的链接，只包含文件白名单允许的内容。

#### Scenario: 项目含秘密
- **WHEN** 项目包含 `.env.local`、私钥、SQLite 数据库和外部符号链接
- **THEN** 下载包不包含这些内容，保留仅有占位值的环境变量示例

### Requirement: 导出失败可识别
系统 MUST 在打包失败时提供明确错误，不将损坏的归档报告为下载成功。

#### Scenario: 缺失源目录
- **WHEN** 用户导出不存在或无法读取的项目目录
- **THEN** 系统返回可理解的失败状态，工作台提供重试入口

### Requirement: 源码包与已验证部署包区分
系统 SHALL 允许下载尚未验证的源码草稿，但只有与验证成功快照匹配的包才能标注为已验证部署包。

#### Scenario: 构建后继续修改
- **WHEN** 用户在成功构建后修改源码并直接导出
- **THEN** 包标记为未验证草稿，或导出先前已验证的固定版本，不沿用旧版本验证结论
