# 规划阻塞排查与预览优先改动

## 线上证据

只读请求用户提供项目 `p_mwhfvs22j7hyhb` 的 `/api/projects/{id}/generation`，获取任务 `run_mwhga5eaurjmn0`。抓取时任务为 running/plan，后端心跳仍更新；最新告警是三个“验收ID、路由或步骤不合法”。没有取消或重启线上任务，也没有发送新的生成请求。

该记录证明至少这一轮并非 Docker 初始化阻塞：文件计划尚未通过强制业务验收对象校验，代码生成还未开始。现有日志合并了缺失/重复 ID、非法路由、空步骤和步骤数量限制等原因，未保存模型原始响应，因此不能从这条日志断言具体哪个字段错误。

## 原因

1. `runPlanStage` 把验收脚本格式、AC 编号覆盖和业务文件计划绑定。即使页面/文件实现结构合法，也会因辅助脚本失败而重写整份计划，最多两轮。
2. 规划使用非流式 generateText，却配置 firstChunkMs/chunkMs。SDK 明确忽略这两项，单次调用只能受总时限约束，默认最长五分钟；另有 SDK 内部重试，缺少逐块进度。长等待不等于无限等待，但页面体验接近卡住。
3. 原候选验证必须启动 Chromium 并逐项执行 AC；缺少浏览器、选择器不匹配或测试数据预期错误，即使已经构建成功也会阻断预览。
4. 实际 SDK 测试发现 textStream 会过滤 error/start 等事件：仅消费文本不能可靠感知错误。若不显式处理 error/abort，流结束后等待 finishReason/usage 也可能悬挂。因此本次规划转换流式时增加错误转中止和元数据期限。

## 新行为

默认 `GENERATION_VERIFICATION_MODE=preview`，无需新增配置即可生效：

- 规划只强制校验业务页面覆盖、文件路径、依赖顺序与数据层结构。acceptance 缺失、对象不合规及 AC 编号不覆盖不再触发重写；旧计划恢复时也不被这些字段阻断。
- 给模型使用更短的预览计划提示词，不要求同时生成可执行验收脚本。仍要求真正实现需求、页面、交互和数据持久化，禁止通过删页面或占位计划缩小需求。
- 规划改为流式请求，记录有节制的字符接收进度；首响应、断流、总时间与最终元数据等待均受限。关闭 SDK 隐式重试；网络/认证/超时直接给出可恢复失败，仅结构化输出问题允许一次纠正。部分/超大/截断计划不写入磁盘。
- 保留安装、类型检查、真实生产构建、隔离候选启动、健康检查及 HTTP HTML 首页检查。首页重定向仅允许同应用路径，最多五次；500、非 HTML、外部跳转不会伪报成功。
- 默认不启动 Chromium、不跑逐项业务脚本，不等待截图或视口检查。报告只声明技术预览通过，`businessVerified` 保持 false。
- 显式 `GENERATION_VERIFICATION_MODE=full` 可恢复原有业务脚本和真实浏览器检查。旧预览与执行隔离保持原有保护。

## 上线范围
