# 共享模板依赖与快速开发预览

## 已实现的启动路径

项目源码 → 校验已有依赖身份 → 关联共享模板依赖或复用独立依赖 → 启动或复用 dev 服务 → 打开预览。

兼容固定模板的项目在 Docker / Linux bubblewrap 环境中共用一份平台管理的 node_modules，通过命名空间只读挂到各自项目的 node_modules。项目内不放指向外部目录的软链接，不改变文件工具路径校验。源码、业务 SQLite、.next、端口及进程仍按项目隔离。

共享键区分模板清单、pnpm 工具链、registry、Node 运行时、系统架构及容器镜像。新增依赖、修改脚本/安装配置或锁文件冲突会使用独立安装；macOS 原生环境沿用独立 CoW 复制。不是所有任意版本的应用混用一个可写目录。

兼容的已有项目下次准备预览时也会尝试关联共享依赖。旧服务停止且新只读挂载服务成功监听后，才回收项目内旧 node_modules 的内容；失败不提前清理。重复打开同一项目复用服务，不触发安装或复制。

## 缓存与配置

默认启用 `SHARED_TEMPLATE_DEPENDENCIES=true`，同时依赖已有的模板复用开关。缓存放在 `TEMPLATE_CACHE_ROOT` 下 `template-shared-v1-{key}`，可信关联记录放在平台 SQLite `SHARED_DEPENDENCY_DATABASE_PATH`（默认 data/shared-dependencies.db，WAL）。这些位置必须在用户项目工作区之外，平台运行用户必须可读写。

平台进程第一次访问每份缓存时异步完整校验，认证结果在同一进程内复用；并发等待不会重复校验整棵目录。重启平台后重新认证。后续启动只检查小型身份元数据，不再逐项目复制/遍历整份依赖。封存目录禁止宿主管理员原地修改；此信任边界依赖平台独占管理及用户只读挂载。发现损坏后停止新共享使用并回退独立安装，保留原缓存以免破坏已有挂载。

关闭共享后，公开预览流程会先恢复独立依赖再启动，不要求用户下载或上传源码。已发布生产版本保持独立依赖与数据边界。不要在应用运行中手动删除全局共享缓存。

首次全局缓存准备仍需安装依赖及编译原生模块；新平台进程首次校验及 Next 首次页面编译也需要时间。本改动消除每项目重复安装/恢复复制，不承诺完全没有编译。
