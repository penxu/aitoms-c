# 默认开发环境预览

用户明确请求不进行生产构建，直接使用 dev 环境预览。沿用已授权的预览优先流程：默认 preview 模式使用 Next dev；full 模式保留生产构建与完整验收，正式 release 发布始终生产构建。

## 改动

- 生成验证：准备依赖、保留类型和导入检查，创建候选源码快照后直接启动 next dev --webpack，不执行 next build，不触发全站预渲染。
- 候选探活与最终预览均选择 dev，注入 NODE_ENV=development 和既有子路径环境；冷启动首页检查允许60秒。
- 聊天 start_service/restart_service、页面启动/刷新入口同样在默认模式跳过生产构建，运行新快照；runner 即使存在旧 BUILD_ID 也优先 dev。
- 聊天规范明确预览不需要手动运行 build。报告和页面使用“开发预览已就绪”，生产构建标记 skipped；不虚报生产可发布。
- 保持旧预览切换与失败回滚、取消、真实服务检查、项目隔离和数据目录保护；发布引擎不变。

## 验证

回归覆盖默认无 build、残留 BUILD_ID 不抢回生产模式、开发环境变量、候选和正式预览模式一致、聊天预览刷新不构建、报告不声称生产构建通过；full 和正式发布继续原行为。运行全量测试、类型、lint及平台自身构建。条件允许时启动真实 Next dev，验证子路径首页、资源、API和停止清理。
