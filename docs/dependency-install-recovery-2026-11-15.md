## 本次改动

- 成功安装的依赖，只有清单、锁文件、执行环境、固定 pnpm 工具链指纹一致且直接依赖及命令入口完整时才复用。候选目录独立复制，避免重新运行 pnpm 更换 store 导致重建。清单变更、环境变化、检测到的直接依赖/入口缺失和显式添加包仍走安装。成功安装标记及直接入口检查不是所有传递依赖文件或原生二进制的完整校验；预览仍需要真实启动验证。
- 安装使用 append-only 日志，单次 fetch 30 秒、重试一次，保留原有五分钟进程超时；这些限制不保证所有安装在一分钟内完成。
- 对话安装工具持续展示最新输出及等待时间，只有最终结果才结束运行状态；停止消费会取消安装。生成阶段和候选复制通过已有事件记录进度。命令末尾错误被保留，常见凭据在进度中脱敏。
- 保留工程命令隔离、超时、取消和候选/旧预览保护。未对线上文件、权限、进程作修改。

## 线上使用

先把包含本次修复的代码部署到平台，再在平台读取的环境文件或面板环境变量中设置：

```dotenv
PACKAGE_REGISTRY=https://registry.npmmirror.com
GENERATION_VERIFICATION_MODE=preview
```

保留平台自身生产运行方式。在 OpenCloudOS 9 主机安装 `dnf install -y python3 make gcc gcc-c++`，再用 `runuser -u www -- /usr/bin/python3 --version` 验证系统 Python。Conda 的 root 环境不代表隔离环境中有 Python。原生隔离安装也可能需要下载对应 Node 头文件，网络错误需按实际日志处理。在面板重启平台服务让代码与配置生效，然后重试原项目的验证/预览，不需要删除代码或项目数据。仅对旧版执行 `npm config set registry` 无法改变原来写死的参数。

如果仍失败，提供此次项目地址和安装日志最后几十行。重点区分 `ERR_PNPM_FETCH`/超时、`prebuild-install` 下载失败、`node-gyp`/编译器错误、磁盘空间或内存问题。切换 npm 镜像不等于解决原生模块的其他下载源；不要通过关闭隔离或跳过必要依赖来声称预览成功。
