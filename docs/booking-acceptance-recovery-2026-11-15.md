# 预约应用验收故障修复

项目：`p_discussion_wait_20261115`。原失败任务：`run_mwh67qk54agka6`。修复后验证任务：`run_mwh9lmc9h15kaw`。

## 已确认的根因

1. 浏览器持有本地生产预览的 Secure 会话 Cookie，同一用户在浏览器内请求 `/api/bookings` 返回 200，而 Playwright 独立 APIRequestContext 返回 401。独立请求和真实浏览器的本地 Cookie 行为不一致。
2. AC-04/05/06/07 在点击注册后直接跳转，可能中断尚未结束的注册请求。登录后有三个同名“预约”链接，即使登录完成也无法唯一定位。
3. AC-03 的“超长”备注只有几十字，未超过代码规定的 200 字上限，实际是合法输入。
4. 列表首屏仅使用服务器查询结果，没有请求 `/api/bookings`，所以浏览器请求拦截不会触发错误状态；加载失败及重试路径也未实现。预约详情的自定义用户栏还覆盖了统一退出入口。

## 修复

- 平台 API 验收改用浏览器内的同源 fetch，继承会话与 mockRequest 拦截，不关闭认证。失败诊断始终包含实际响应内容。
- 生成提示要求先断言异步注册/登录成功，再执行后续导航；重复列表入口使用唯一可访问名称；非法输入样本实际越过业务边界；区分浏览器接口错误注入与服务器直接查询。
- 当前预约项目给时段入口增加唯一名称；用例等待已登录用户出现，超长备注改为 201 字。保留创建、重复冲突、取消、持久化和错误重试的全部断言。
- 列表增加真实加载、独立错误状态、可执行重试、卸载时中止请求；服务器初始列表查询失败可交由列表错误界面展示。详情与列表恢复统一退出入口。
- 预约源码及计划均通过平台编辑 API 修改，经过项目路径校验与写入锁。
