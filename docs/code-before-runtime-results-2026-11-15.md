# 代码先生成、运行环境后准备

## 行为

新项目的准备工程只创建目录和模板文件。理解需求、规划结构与编写代码继续使用原来的持久化规格、计划、事件和文件 checkpoint，不等待 Git 或依赖缓存的运行时探测。

只有进入运行验证后才准备隔离执行后端、安装依赖、构建和启动服务。Git 提交延迟到验证成功；不再承诺每个早期阶段都有 Git commit。路径安全和执行隔离保持原有边界。

运行环境准备失败时，任务停在 verify，页面显示“代码已生成，运行验证尚未完成”，可查看或下载已有源码，并通过“仅重试运行验证”复用已有代码。刷新及仅验证续跑时，前五阶段根据持久化 verify 状态恢复为完成。未通过验证不会报告 ready 或新的可用预览。

旧预览保护保持不变：已经运行在独立候选目录的预览继续访问旧版本；历史上直接运行工作区根目录的预览，仍先完成安全快照迁移，再允许修改源码。迁移受阻时不能为了生成新代码而损害旧预览。

## 验证证据

- 新增/扩展回归先观察失败，再修改实现：覆盖不可用运行环境、复制中断续跑、原文件保护、前五阶段无 Git、verify-only 续跑、环境错误与取消、刷新时阶段恢复。
- 重点回归：26 项通过。
- 完整回归：267 项通过，0 失败，0 跳过。日志 `/tmp/atoms-code-first-tests-full.log`。
- `npm run typecheck`、`npm run lint` 和 `npm run build` 均成功。生产构建日志 `/tmp/atoms-code-first-build.log`。
- 实际渲染 GenerationSummary 与 GenerationTimeline：验证失败时均显示保留代码状态和“仅重试运行验证”按钮，且不显示应用构建成功。渲染产物 `/tmp/atoms-code-first-GenerationSummary.html`、`/tmp/atoms-code-first-GenerationTimeline.html`；这是组件渲染检查，不是线上浏览器验收。
- 完整回归需要访问本机 Docker 与测试进程身份；受限沙箱中的第一次全量运行因该限制有 1 失败和 7 跳过，获准在正常本机权限下重跑后全部通过。没有通过修改测试绕开真实隔离检查。
- 独立只读代码审查未发现阻塞问题，覆盖前五阶段调用链、验证续跑、刷新展示、旧预览保护与隔离边界。

## 线上应用

这些修改位于本地工程，尚未同步到 `/www/wwwroot/aitoms-c`。线上需更新对应源码，在 `app` 目录重新生产构建并重启平台；启动时仍要初始化服务用户附加组（此前已用 runuser 验证）。不得覆盖线上 `.env.local`、数据库或项目目录，也不能用本机 node_modules 覆盖服务器依赖。

线上之前停在 scaffold 的任务，应从准备工程阶段重试，之后会继续生成代码。新版进入 verify 后因环境失败的任务，才使用“仅重试运行验证”。

此改动不会使全栈应用脱离运行环境执行，也没有修复服务器访问镜像仓库或软件源的网络问题。Docker 不可用时现在可以先得到源码；真实预览仍需 native 或 Docker 后端可用。当前前台 runuser 启动仍需另行配置成持久托管。
