# 生成后无法构建与预览：排查记录

## 已复现的原因

1. `p_mwg59j4y5qdwf4` 从旧 npm 布局缓存恢复依赖后，`.bin/tsc` 与 `.bin/next` 的符号链接让 pnpm 生成命令包装时覆写真正的 JS 入口。命令行稳定复现 `basedir=$(...)` 被 Node 解析产生 SyntaxError。
2. 本地平台长期运行进程继承了 CodeBuddy 的旧任务删除保护上下文，Next.js 清理生成产物时遇到 `SAFE_DELETE_BULK_CONFIRM_REQUIRED`。反复修改应用业务代码无效。
3. 工作台只要历史生成状态为 failed 就占据预览区域，即使服务已正常运行也不创建 iframe。
4. 启动接口原来只创建子进程就返回 running，未等待页面就绪，也未捕获启动日志。

## 修复

- 缓存使用新的 pnpm-v2 命名空间，检查命令入口和 .bin 布局，不再复用旧 npm 缓存。
- 缓存和项目独立复制，不共享可写硬链接；保留内部相对符号链接。
- 坏依赖隔离到工程 `.atoms/dependency-backups/<时间>/node_modules`，保留排查证据；该目录被 node_modules 源码白名单排除和 Git 忽略规则覆盖。
- 启动等待 HTTP 就绪并返回捕获的真实错误；旧进程退出不能清除重启后的新进程状态。
- 已运行项目优先显示 iframe，执行记录可单独打开。
- 删除保护归类为基础设施错误，立即给出处理指引，不触发业务代码自动修复。
- 用户明确授权后清理两个工程的 .next，并用标准 npm run dev 重启本地平台。未更改 CodeBuddy 保护配置。

## 旧任务无法继续与卡住（后续排查）

浏览器使用 POST 拦截复现：失败工程 p_mwg3g426i2l0vk 输入“继续修复原来的应用”被发送到 `/generate` 且没有 resumeFrom，因此重新经历 SPEC/PLAN/BUILD。历史运行中也出现“为什么失败了”被保存为新 requirement。这是旧任务越重试越乱的明确原因。

修复：服务端确定工程是否已有文件、消息或生成记录，前端只给全新空工程提供一句话生成；失败或中断的旧任务输入走 `/api/chat`，明确点击重试按钮才从阶段续跑。带 q 的旧链接也不能自动重建已有工程。浏览器再次拦截验收，已完成和失败旧项目都只提交 `/api/chat`。
