# 直接开发预览

用户已确认的默认流程：项目源码 → 复用已有依赖 → 启动或复用 dev 服务 → 打开预览。

## 行为

- 生成完成、工作台运行按钮和聊天 start_service 使用项目根目录源码；编辑保存及继续生成在默认 preview 模式不再准备基线候选。
- 已安装依赖的成功指纹匹配时，不执行 pnpm install、不复制项目或 node_modules。依赖/锁文件/运行环境变化或安装不完整时才准备依赖。
- 普通运行复用已核对身份、根目录及依赖指纹的 dev 进程和端口。显式重启、依赖变化或旧候选切回根目录时才切换服务。
- 启动指纹保存在 SQLite runtime_identities 的增量 dependency_key 列中，覆盖“独立安装工具已完成，随后才点运行”的情况。旧记录首次运行时可以重新启动以建立指纹。
- 旧候选切换失败恢复原服务；调用者取消贯穿端口分配、运行时准备与启动等待。路径校验、进程身份、端口池、命令隔离与变更租约保持。
- 普通开发源码写错时，dev 可以直接显示编译错误，修改后恢复。默认预览不再承诺冻结旧页面。full 验证和正式发布继续使用独立快照、数据和构建流程。
- Next dev 首次打开页面仍需要按需编译；省掉的是复制副本、重复安装和不必要的进程重启。

## 验证

针对测试覆盖普通运行、显式重启、依赖更新、安装失败/取消、默认与full编辑/生成、旧候选切换恢复和启动中取消。

- 完整单测343项通过，0失败、0跳过；lint、类型检查、平台构建通过。
- 真实runCommand/runner隔离测试：匹配依赖未执行安装，项目根目录连续运行返回相同PID/端口，未创建候选目录。Chrome打开新建弹窗正常，修改根源码触发HMR并更新页面，源码修改后再次运行仍复用同一PID，显式重启生成新PID；未产生生产BUILD_ID。测试项目、进程和独立业务数据已清理。
- 回归覆盖旧候选切回根目录失败恢复、独立安装后的指纹变化、端口准备期间取消；独立只读审查发现的问题已修复并复审通过。
- 命中已有依赖时直接返回，不等待下载缓存回收；实际新安装仍保留缓存清理。

本地真实运行使用独立测试工程验证，不代表线上平台已部署更新。

## 部署边界

这是平台逻辑更新，需要按已有部署方式更新平台版本并重启平台服务，才能影响线上运行按钮和生成流水线。不需要逐个下载/上传生成应用，也不要求为生成应用执行生产构建。已存在的候选预览在新版平台的下一次普通运行时切回项目根目录。
