# 应用设计讨论验收记录

## 交付行为

- 在工程脚手架之前增加需求分析。仅在应用目标或关键业务有歧义时暂停；清晰需求直接进入原流程。
- 公开展示需求理解、已明确事项、关键问题、二至四个候选方案、推荐提示及自由补充。每轮最多三题；两轮后仍不明确时展示最终假设，必须由用户明确确认或补充决定。
- “确认选择并继续”和“采用推荐方案继续”均由用户触发。等待期间没有悬挂的模型请求、后台任务或工程写入租约。
- SQLite 保存问题版本与确认答案，原始需求保留。刷新、断线及平台进程重启后恢复同一任务的问题。
- 同一项目的运行和等待任务共同受唯一性约束。等待期间阻止其他代码修改；提交校验版本与任务归属，重复答案幂等，冲突或迟到答案拒绝。取消后不能靠提交答案复活。
- 回答用于后续 SPEC、计划与代码实现；失败续跑复制已确认决定。
- 通过任务编号订阅原任务。即使回答后任务立刻结束，也保留真实结果，不再用空启动请求覆盖状态。

## 真实模型与浏览器验收

| 场景 | 结果 |
| --- | --- |
| “帮我做个管理系统” | 真实模型返回三项关键问题；任务 waiting，工程文件树为空 |
| 问题卡片 | 桌面与 375px 手机布局可用，键盘可选，无横向溢出，无浏览器页面错误 |
| 刷新 | 恢复同一任务与相同问题版本 |
| 临时提交失败 | 浏览器模拟 503；输入保留，重试成功 |
| 提交并恢复 | 继续原 run，答案持久化；重复提交 reused，冲突回答 409 |
| 明确掷骰子需求 | 真实模型直接开始工程阶段，无讨论问题；运行中取消成功 |
| 等待状态取消 | 取消成功，迟到回答返回 409；重新讨论可恢复 |
| 平台重启 | 确认无运行生成与写入租约后重启本地平台；同一等待任务、问题版本与内容完整保留 |
| 终态竞争 | 浏览器模拟回答后立即失败；原始错误保留，无空启动请求 |
| 真实应用交付 | 根据讨论中的个人待办选择生成 SPEC，构建通过，7 项业务验收与 1 项页面检查通过 |
| 重启后应用预览 | 真实手机浏览器访问生成应用返回 200，页面正常，无页面错误 |

真实生成第一次在一个文件上遇到模型语法错误，平台如实报告失败。随后通过原有 build 阶段续跑完成，未手工修改生成应用源码；已确认的讨论选择在新 run 中仍保留。因此本记录不表示模型输出始终一次成功。
